## 2. 구현이 실제로 수행한 것

1. **MOS TX + 채널:** 256개 PRBS7 비트를 DB HiTek 180 nm 8:4:2:1 NMOS 출력단의 2-Tap FFE 코드로 변환하고, 2-Pole RC 근사 채널에 연결한다. ngspice로 실제 전압 파형 `v(rx)`를 생성한다.
2. **CDR 위상 복구:** 수신 아날로그 파형 `v(rx)`, 0.25 V 기준 전압, 명목 3.6-Gb/s UI, 이전 회복 위상만 사용한다. 데이터 임계값 통과 시각 `t_k`에서 `(t_k / T_{RX}+0.5) mod 1`을 이용해 가장 가까운 복구된 데이터 중심 위상에 대해 누적 위상 보정을 적용한다. 송신 PRBS 정답, 비트 에러, RX Latch 결과는 **위상 제어에 입력하지 않는다**.
3. **물리 MOS 수신 판정:** 이 복구 타이밍을 전압 PWL로 표현하고, 동일 DB HiTek PDK의 두 PMOS 입력 재생 Latch를 실제 ngspice에서 다시 시뮬레이션한다. 양쪽 Latch는 1.8-GHz Half-Rate 수신으로 교대하며, 원래 수신 클록의 ±1000-ppm 오차도 실험한다.
4. **사후 평가:** 두 번째 SPICE 시뮬레이션까지 끝난 뒤 송신 PRBS를 이용해 **정수 UI 패킷 시작 지연(-3~+3 UI)**만 정렬하여 오류 수를 계산한다. 이 정렬은 시뮬레이션 평가용이며 실제 수신기에 별도 Framing/Sync 회로가 필요하다.

**데이터 위상 업데이트 식:** `phase[k+1] = phase[k] + 0.15 × wrap((t_edge/T_RX + 0.5) − phase[k])`. Phase는 반드시 **unwrapped** 상태로 저장해야 한다. 0/1 UI 경계에서 단순 Modulo를 적용하면 1 UI Cycle Slip이 발생할 수 있다. 해당 오류도 수정하고 재검증했다.

## 3. 검증 수준 및 미구현 항목

**이것은 2-Pass Causal-Waveform Replay / Co-simulation이다.** 첫 SPICE 실행의 이미 생성된 전압 파형을 두 번째 SPICE 회로의 클록 입력으로 제공한다. Phase Controller는 이벤트를 시간순으로 갱신하지만 Python에서 실행되므로, 실제 회로 내에서 MOS VCO와 RX Latch가 실시간으로 데이터를 피드백하여 상호작용하는 폐루프는 아니다.

- 복구 클록은 이상적인 PWL Source다. 실제 MOS VCO 출력, 데이터 Phase Detector MOS 회로 및 Charge Pump을 이용한 닫힌 Physical CDR은 미구현이다.
- 송신기 Digital Pre-driver와 PLL/PFD 및 전체 RX 출력 Demux도 물리적으로 완성하지 않았다.
- 실제 케이블의 Full-Complex RG58/FR4 S-parameter 대신 −12 dB @1.8 GHz를 맞춘 2-Pole RC 모델을 썼다.
- 187비트 관측 무오류는 BER 10⁻¹²의 검증이 아니며, 지터/잡음과 데이터 패턴의 다양성에 대한 장시간 통계 검증도 아니다.
- ngspice가 파운드리 HSPICE 모델 Parameter 일부를 무시한다. HSPICE 수치 상관 테스트는 미완료다.
