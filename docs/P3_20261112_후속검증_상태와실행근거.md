## 1. 이 문서의 목적

이번 후속 검증은 이미 확인된 단순 PDK 코너 통과를 **온도, 전원전압, 장기 수렴, Cycle Slip**으로 확장하고, 수신 데이터 기반의 동일 넷리스트 물리 MOS 위상 피드백과 실제 CMOS Pre-driver 조건에서의 FFE 개선 주장을 반증 가능하게 시험한다.

검증의 성공, 기능 실패, 미실행은 서로 다른 상태로 기록한다.

- **실행 성공, 전기적 시험 통과:** 실제 ngspice가 파형을 계산했으며 사전에 정의한 판정 기준을 통과.
- **실행 성공, 전기적 시험 실패:** 실제 ngspice 파형이 존재하지만 목표 주파수, 위상, 수신 판정 또는 Cycle Slip 기준을 충족하지 못함.
- **실행 전 CI 인프라 실패:** GitHub Actions Job이 Runner를 배정받지 못해 실제 회로를 실행하지 못함. 회로 동작 실패로 계산하지 않음.
- **원본 참조 데이터 부재:** 별도 측정 채널 또는 라이선스된 HSPICE 참조 파형이 없어 원 논문의 동일성 판정 불가.

## 2. 공통 설계의 실제 온도 및 공급전압 검증 (실행 완료)

### 2.1 동일한 물리 MOS PLL 설정

이전에 27°C TT/FF/SS/FS/SF 조건에서 단순 수렴 기준 5/5를 통과한 아래 설정을 변경하지 않고 시험했다.

- 180 nm DB HiTek SVT MOS charge pump 소스와 싱크 전류원 폭: 원래 독립 재구성 회로 크기의 **82.5%**.
- MOS VCO 3단 각각 추가 Load Capacitance: **3 fF** (파운드리 Extraction이 아닌 설계 변수).
- 공통 초기 제어 전압: **1.02 V**.
- 이상적 기준 450 MHz, 실제 MOS VCO 목표 1.8 GHz, MOS 코어 전원 1.8 V nominal.
- XSPICE 디지털 PFD/4, MOS 전류 스위치, MOS VCO 및 필터가 하나의 ngspice 넷리스트에 연결된다.

### 2.2 이전보다 엄격한 판정

기존의 (i) VCO 평균 주파수 오차 1500 ppm 미만, (ii) 기준 클록과 VCO 최근접 Edge의 결정론적 위상 차이 표준편차 8 ps 미만, (iii) 물리 MOS VCO Gate Ripple 5 mVpp 미만 외에 다음을 추가했다.

1. 최종 80 ns에서 450 MHz Reference의 인접 두 Rising Edge 사이에 실제 VCO Rising Edge가 정확히 **4개** 나타나는지 검사해 주파수 기반 Cycle Slip을 탐지한다.
2. 종료 전 중복되지 않는 3개 80-ns 구간에서 측정한 평균 VCO 주파수의 최댓값과 최솟값 차이가 **2 MHz 미만**인지 검사한다.
3. 실제 MOS 공급전압에 맞게 DAC gate-high와 PMOS complementary VCO control을 변화시킨다. 기준 클록은 외부의 이상적인 1.8-V domain으로 유지한다.

## 3. 실제 MOS 위상 보정 CDR의 PRBS31 반복 검증

실제 CMOS TX, MOS 동적 재생 RX Latch, XSPICE Reference PLL, 물리 MOS Charge Pump 및 2단 MOS 수신 클록 지연단을 연결한 동일 ngspice 넷리스트를 사용했다. 수신 데이터에 대한 Phase Detector는 **행동 모델 B-source**이며, RX 파형의 전압만 감지한다. 송신 정답 PRBS31은 MOS 시뮬레이션 종료 후 비트 프레이밍과 비교 평가에만 사용했다.

총 32조건: PRBS31 시드 2개, -0.05/+0.95 UI의 시작 위상 2개, Gain -200/0/+80/+160 μA, 실제 제어 커패시터 0.8/1.6 pF. 모든 경우 시뮬레이션은 실행됐지만 0 Error가 전 영역에서 성립한 것은 아니다.

| 대표 조건 | 피드백 미적용 | 데이터 기반 물리 피드백 | 의미 |
|---|---:|---:|---|
| PRBS31 0x13572468, -0.05 UI, 0.8 pF | 34/156 | -200 μA에서 6/156 | 조건부 개선 |
| PRBS31 0x54C4EE17, -0.05 UI, 0.8 pF | 40/156 | -200 μA에서 11/156 | 조건부 개선 |
| PRBS31 0x54C4EE17, +0.95 UI, 0.8 pF | 36/156 | -200 μA에서 6/156 | 조건부 개선 |
| PRBS31 0x13572468, +0.95 UI, 0.8 pF | 30/156 | -200 μA에서 70/156 | **다른 PRBS에서는 악화** |

[실행 원본](https://github.com/khi103/EEE6682-Presentation/actions/runs/43214985026), [코드](../simulation/p3_prbs31_live_mos_cdr_sweep.py).

**판정:** 실제 MOS Delay Phase Actuator를 수신 데이터로 제어할 때 효과가 관측되지만, **알려진 패턴과 위상에 대해 일관되게 Lock 하는 CDR는 미구현**이다. 특정 성공 조건만 골라 전체 Lock Range처럼 보고하지 않는다.

## 4. XSPICE 4-XOR 기반 디지털 위상 검출기: 구현과 미입증

[실험 코드](../simulation/p3_xspice_4xor_mos_cdr.py)에 XSPICE ADC, 수신 데이터/클록 샘플링 DFF, 네 개의 d_xor, Digital-to-Analog Bridge 및 실제 MOS Delay Capacitor를 물리 TX/RX/PLL과 통합했다.

시험한 이득 -20/0/+20/+100 μA, 시작 위상 -0.05/+0.95 UI에서 **실제 SPICE 전기적 실행은 성공**했다. 그러나 동일 입력 조건의 유효 MOS RX 오류 수는 Gain 값과 관계없이 -0.05 UI에서는 40/156, +0.95 UI에서는 36/156으로 유지됐다.

[4-XOR 시뮬레이션 원본](https://github.com/khi103/EEE6682-Presentation/actions/runs/43215787203), [DAC 출력 진단을 추가한 후속 시도](https://github.com/khi103/EEE6682-Presentation/actions/runs/43216227591).

따라서 현재 4-XOR 구현은 **유의미한 데이터 위상 제어가 확인되지 않았음**. DFF의 Data/Edge phase allocation, XOR UP/DOWN collision, Counter/Decimation 및 MOS phase-actuation gain에 대한 구조적 디버깅이 필요하다. 이것을 원 논문 Fig.19의 실제 구현으로 소개해서는 안 된다.

[미실행 GitHub Actions](https://github.com/khi103/EEE6682-Presentation/actions/runs/43216565398). 이 테스트의 결과를 전기적 실패나 성공으로 표시하면 안 된다.

## 6. 실제 MOS RX Offset Calibration

기존 검증에서는 물리 MOS 4-bit Binary Weighted Current-Sink DAC를 수신 기준 게이트에 연결해 +30 mV 오프셋 조건에서 90/358 invalid or incorrect MOS latch decisions를 2/358로 줄였다. 코드 9는 실제 물리 MOS DC Sweep으로 0.25V target에 가장 가까운 조건을 선정했고, 송신 정답 비트는 코드 선정에 사용되지 않았다. [실행 근거](https://github.com/khi103/EEE6682-Presentation/actions/runs/43178073053).

이번에는 자동 피드백을 시험하기 위해 실제 MOS Current Sink, 3 kΩ 레퍼런스 저항, 적분용 MOS 노드 커패시터, RX 기준 전압만 감지하는 행동 모델 B-source 제어기를 **같은 SPICE 회로** 안에 구현했다. [코드](../simulation/p3_auto_mos_rx_offset_servo.py).

자동 Calibration의 6개 케이스는 GitHub Actions Runner가 배정되지 않아 **미실행**이다. [GitHub Actions](https://github.com/khi103/EEE6682-Presentation/actions/runs/43216917313). 따라서 자동 오프셋 보정 동작은 아직 입증되지 않았으며, 이전 DC 코드 선정과 물리 DAC 트랜지스터 검증만 확인된 상태다.

## 7. CI 인프라 미실행과 회로 실패의 구분

두 최신 실험에서 GitHub Actions Job은 2–3초 내에 종료되었으며, **Runner ID = 0, Runner Name 없음, \`steps=[]\`, Job Log BlobNotFound**로 확인된다. 또한 정상적으로 성공하던 별도의 Behavioral Reproduction Workflow도 같은 시간대에 Runner 배정 없이 실패했다.

- [512비트 물리 CMOS 링크 미실행](https://github.com/khi103/EEE6682-Presentation/actions/runs/43216565398)
- [물리 MOS 자동 RX 오프셋 보정 미실행](https://github.com/khi103/EEE6682-Presentation/actions/runs/43216917313)
- 동일 CI 재실행도 Runner 배정에 실패.

이 현상의 계정 과금, 분당 사용량 제한, 리소스 제한, 정책 또는 서비스 인프라 장애 중 **어떤 원인인지 확정할 증거가 없다**. GUI의 Actions 결제/사용량 및 Repository Settings의 실행 정책은 계정 관리자가 확인해야 한다. 이 두 작업은 **회로 시뮬레이션이 계산되지 않았으므로 전기적 FAIL로 기록하면 안 된다**.

## 8. 최종 실측 BER와 오류 통계의 경계

0건의 오류를 N개의 독립적인 동일 확률 비트에 대해 관측했다는 가정하더라도, 95% 신뢰도에서 오류 확률의 1-sided 상한은 다음과 같다.

\[
p_{\mathrm{upper},95\%}=1-0.05^{1/N}.
\]

- 0/356개의 **유효하게 재생된** 비트: 상한 약 0.00838, 즉 0.838%. 누락된 나머지 2개의 UI는 BER 계산에서 임의로 제외할 수 없으므로 실질 수신 시스템의 검증은 더 제한적이다.
- 0/378개 비트: 상한 약 0.00789, 즉 0.789%.
- 오류가 0개인 독립 비트만으로 BER 10^-12 이하의 상한을 동일 신뢰도로 증명하려면 약 \(2.996\times10^{12}\)비트가 필요하다. 3.6 Gb/s의 실제 시간으로 약 832초(13.9분)이나, 이러한 길이의 **전체 트랜지스터 수준** SPICE 시뮬레이션은 현재 과제 환경에서 현실적이지 않다.
- 동일 PRBS 패턴 반복, 최적화된 샘플링 타이밍, 잡음/지터가 없는 조건이라면 이 통계적 독립성 가정도 성립하지 않는다.

이 수치는 논문 Fig. 25 실측 Eye 37 mV × 189 ps 및 실측 전체 Power 27.12 mW를 재현하지 못한다는 점과 양립한다. 논문의 보고 수치를 현재 독립 MOS 테스트벤치 결과로 대체하면 안 된다.
